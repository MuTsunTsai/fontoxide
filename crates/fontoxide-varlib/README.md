# fontoxide-varlib

A Rust port of [`fontTools.varLib`](https://fonttools.readthedocs.io/en/latest/varLib/):
building variable fonts from masters and a designspace, instancing them (fully
or partially), and the related tools (`avar`, `featureVars`, `interpolatable`,
`mutator`, variation models, …). It is part of
[fontoxide](https://github.com/MuTsunTsai/fontoxide), a port of fontTools to Rust.

Most projects should depend on the [`fontoxide`](https://crates.io/crates/fontoxide)
crate, which re-exports this one as `fontoxide::varlib` (feature `varlib`, on by
default). Depend on this crate directly to keep the dependency tree small.

## Example

```rust,no_run
use fontoxide_ttlib::{Font, ReadOptions, WriteOptions};
use fontoxide_varlib::instancer::{AxisLimits, AxisTriple, InstancerOptions, instantiate_variable_font};

let mut font = Font::read(std::fs::read("Variable.ttf")?, ReadOptions::default())?;
let mut limits = AxisLimits::new();
limits.insert("wght".into(), Some(AxisTriple::pin(700.0)));
instantiate_variable_font(&mut font, &limits, &InstancerOptions::default())?;
std::fs::write("Bold.ttf", font.write(&WriteOptions::default())?)?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

## Compatibility

This version follows **fontTools 4.68.0**. The instancer's output is the same as
fontTools', byte for byte, as checked against fontTools on a corpus of fonts;
the other modules are checked with fontTools' own tests and with fixtures
generated by running fontTools. Removing overlaps while instancing gives a
geometrically equivalent result, not an identical one, and the plots of
`varLib.interpolatable` are not ported (the problems it finds are available as
data). Differences from fontTools are listed in
[COMPATIBILITY.md](https://github.com/MuTsunTsai/fontoxide/blob/main/COMPATIBILITY.md).

The crate is pure safe Rust and builds for `wasm32-unknown-unknown`.
