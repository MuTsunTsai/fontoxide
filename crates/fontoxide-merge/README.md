# fontoxide-merge

A Rust port of [`fontTools.merge`](https://fonttools.readthedocs.io/en/latest/merge.html):
merges several fonts into one. It is part of
[fontoxide](https://github.com/MuTsunTsai/fontoxide), a port of fontTools to Rust.

Most projects should depend on the [`fontoxide`](https://crates.io/crates/fontoxide)
crate, which re-exports this one as `fontoxide::merge` (feature `merge`, on by
default). Depend on this crate directly to keep the dependency tree small.

## Example

```rust,no_run
use fontoxide_merge::{Merger, Options};
use fontoxide_ttlib::WriteOptions;

let mut merger = Merger::new(Options::default());
let mut font = merger.merge_files(&["Latin.ttf", "Arabic.ttf"])?;
std::fs::write("merged.ttf", font.write(&WriteOptions::default())?)?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

On the command line, this is `fontoxide merge` (`pyftmerge`), from
[`fontoxide-cli`](https://crates.io/crates/fontoxide-cli).

## Compatibility

This version follows **fontTools 4.68.0**. Given the same fonts and options, the
output is the same as fontTools', byte for byte, as checked with fontTools' own
tests and with fixtures generated by running fontTools. Differences from fontTools
are listed in
[COMPATIBILITY.md](https://github.com/MuTsunTsai/fontoxide/blob/main/COMPATIBILITY.md).

The crate is pure safe Rust and builds for `wasm32-unknown-unknown`.
