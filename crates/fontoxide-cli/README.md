# fontoxide-cli

The `fontoxide` command: the command lines of
[fontTools](https://github.com/fonttools/fonttools) (`ttx`, `subset`, `merge`,
`varLib.instancer`, `feaLib`, …), as ported by
[fontoxide](https://github.com/MuTsunTsai/fontoxide), a port of fontTools to Rust.
It is also a port of `fontTools.ttx` and `fontTools.__main__`.

## Installation

```sh
cargo install fontoxide-cli
```

`fontoxide <module> args...` runs the command line of a module, as
`fonttools <module> args...` does:

```sh
fontoxide ttx font.ttf
fontoxide subset font.ttf --text="Hello" --output-file=subset.ttf
fontoxide varLib.instancer Variable.ttf wght=700 -o Bold.ttf
fontoxide help
```

With the feature `fonttools-names`, fontTools' console scripts `fonttools`,
`ttx`, `pyftsubset` and `pyftmerge` are installed too, with fontTools' usage and
help texts, as drop-in replacements:

```sh
cargo install fontoxide-cli --features fonttools-names
```

The features `woff`, `graphite`, `pathops` and `repacker` (on by default) are
fontTools' extras; see [`fontoxide-ttlib`](https://crates.io/crates/fontoxide-ttlib).

## Compatibility

This version follows **fontTools 4.68.0**. Given the same input and arguments,
the output files and text are the same as fontTools', byte for byte, as checked
against fontTools on a corpus of fonts and with fixtures generated by running
fontTools, with the exceptions of the library crates (such as compressed data
and overlap removal). Output text always uses `\n` line endings. Differences
from fontTools are listed in
[COMPATIBILITY.md](https://github.com/MuTsunTsai/fontoxide/blob/main/COMPATIBILITY.md).

The commands read and write files with `std::fs`, so they are meant for
operating systems, not for `wasm32-unknown-unknown`; use the library crates
there.
