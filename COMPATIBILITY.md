# Compatibility with fontTools

This version of fontoxide tracks **fontTools 4.68.0** (`fontoxide::FONTTOOLS_VERSION`).

## What "byte-for-byte compatible" means

Given the same input and the same options, fontoxide produces the same output as
fontTools 4.68.0 on CPython with all its optional dependencies installed
(`pip install fonttools[all]`): the same binary font, the same TTX, and the same text
output from the command lines. That includes fontTools' own choices that no
specification dictates, such as table formats, subtable sharing, the order of tables and
the result of overflow resolution (with the HarfBuzz repacker, as `fonttools[all]` has
it).

The exceptions are listed below. Most of them are about invalid input, where fontTools
raises an exception or loops and fontoxide returns an error at a different point (or
handles the input), and about places where fontTools' output depends on Python's hash
seed. For valid input, the differences that remain are compressed data, overlap removal,
and the last digits of some floating-point results across platforms.

The Cargo features `woff`, `graphite`, `pathops` and `repacker` are fontTools' extras.
They are on by default; with one turned off, fontoxide behaves as fontTools does without
that Python package (for example, WOFF 2.0 fails with an `ImportError`).

## How it is checked

- **Ported upstream tests.** `upstream/tests.toml` lists every test in fontTools' test
  suite with its porting status: of 3,784 tests, 3,608 are ported, 176 are not
  applicable, and none are pending. The ported tests use fontTools' own test data and
  expected output (TTX files, feature files, UFOs, …) unchanged.
- **Differential testing.** `cargo xtask parity` runs fontTools 4.68.0 and fontoxide on
  a corpus of fonts (fontTools' test fonts, system fonts, variable, color, CJK, CFF and
  CFF2, AAT and Graphite fonts, collections, fonts with more than 65,536 glyphs, …) and
  compares the output byte for byte: TTX dumps, binary round trips, compiling from TTX,
  subsetting, instancing in several modes, and more. The command lines and the other
  modules are compared with fixtures generated by running fontTools itself.
- **Fuzzing.** The parsers are fuzzed with cargo-fuzz (see `fuzz/`): bad input must
  return an error, never panic.

The tests marked not applicable are about things that have no counterpart in Rust:

- features of Python's object model: dynamic attributes, lazy containers, pickling,
  Python file objects, string-keyed configuration (fontoxide uses typed fields), class
  registries, deprecated Python shims;
- plotting and rendering (FreeType, cairo, matplotlib, the macOS graphics frameworks);
  fontoxide provides the data instead (see below);
- Python's logging infrastructure and stdout redirection; fontoxide logs through the
  `log` crate;
- tests that need packages outside `fonttools[all]` (glyphsLib, ufo2ft, PyFilesystem2
  objects).

## Differences by design

### Compressed data

fontoxide uses pure-Rust implementations of the compression libraries. They do not always
produce the same compressed bytes as the C libraries fontTools uses, so for compressed data
only the decompressed content is guaranteed to match:

| Data | fontTools | fontoxide |
|---|---|---|
| WOFF 2.0 | `brotli` (C), quality 11 | `brotli` crate, same parameters. Small files are identical; larger fonts compress differently (usually within 1% in size). Headers, table directory and decompressed data are identical. |
| WOFF 1.0 with `--with-zopfli` | `zopfli` (C) | `zopfli` crate; occasionally differs by a byte. |
| WOFF 1.0, gzipped `SVG ` documents | `zlib` | `flate2`; the deflate stream can differ. |
| Graphite `Silf` and `Glat` | LZ4 high compression | `lz4_flex`, which has no high-compression mode; the 8-byte header and the decompressed data are identical, and fontTools reads the result the same way. |
| `.ufoz` | Python's `zipfile` | `rawzip` and `flate2`; the files and their contents are the same, the zip container bytes and timestamps are not. |

### Overlap removal

`removeOverlaps` (and the instancer's `overlap=REMOVE`) uses
[linesweeper](https://crates.io/crates/linesweeper) instead of skia-pathops. The result is
geometrically equivalent, not byte-for-byte identical:

- contours can start at a different point and come in a different order;
- fontTools keeps a glyph unchanged when its simplified path is the same; fontoxide ignores
  start points and direction in that comparison, so it replaces glyphs less often (for
  example, a glyph without overlaps but with collinear points may be kept);
- fonts that have both `glyf` and `CFF ` are not supported.

### Plotting and rendering

Drawing to a canvas or a raster is not ported. fontoxide exposes the data instead, so that
it can be drawn with any Rust library:

| fontTools | fontoxide |
|---|---|
| `varLib.interpolatable --pdf/--ps/--html` (cairo) | `Unsupported` error; the problems (with contour, node and start point details), the glyph sets of the masters and `LerpGlyphSet` are available from `interpolatable::test_gen` |
| `varLib.plot` (matplotlib) | the locations and supports of `VariationModel`, `support_scalar` |
| `varLib.avar.plan --plot` | a warning; the plan is computed and written as usual |
| `pens.freetypePen`, `cairoPen`, `reportLabPen`, `qtPen`, `wxPen`, `cocoaPen`, `quartzPen` | the outlines, through the pens (for example `RecordingPen`) |

`.glyphs` input to `varLib.interpolatable` is not supported either.

### Floating-point results across platforms

Some results depend on the platform's math library (`pow`, `hypot`, trigonometric
functions): fontTools itself gives results that differ in the last digits between Windows
and Linux, and some algorithms (such as qu2cu's curve fitting) amplify that. fontoxide
follows CPython's floating-point semantics, and matches fontTools on the same platform.

### Fixed order instead of Python's hash order

Where fontTools iterates over a Python `set`, its output can change from one run to the
next (it depends on `PYTHONHASHSEED`). fontoxide uses a fixed order instead:

- **subset**: the `COLR` v0 layer records of fonts that have both v0 and v1 glyphs follow
  the glyph order (fontTools' behavior since
  [fonttools#4402](https://github.com/fonttools/fonttools/pull/4402), merged after 4.68.0);
  the default value of `bsln` and `prop` lookups, when several values are equally common,
  is the first one in glyph order.
- **feaLib**: language systems are kept sorted; in `LigatureCaretByPos`, an integer comes
  before a variable value with the same default.
- **designspaceLib**: `get_stat_names` lists languages in order of first appearance.
- **ufoLib**: kerning groups renamed by the converters are numbered in order of
  appearance.
- **merge**: duplicate code points in a font's `cmap` are processed in code point order.
- **varLib.interpolatable**: `test_gen` without a list of glyphs checks them in sorted
  order.
- **mtiLib** without `--font`: glyph IDs are assigned in order of first reference.
  (fontTools 4.68.0 cannot run without `--font` at all.)
- **qu2cu** `-v`: the keys of the statistics are sorted.
- Error messages that list the members of a set (in featureVars and reorderGlyphs, for
  example) list them sorted.

### Errors raised earlier

fontoxide stores values in typed fields: fixed-width integers, tags, and glyph IDs rather
than glyph names. Invalid values in TTX or in builder input therefore fail when they are
read, not when the font is compiled. This includes:

- unknown glyph names in OpenType Layout tables and `VARC`;
- integers out of range for their field, in the generated OpenType tables, `COLR` v0,
  `CPAL`, `kern`, the bitmap tables, `fvar`, `SVG `, mtiLib input and colorLib input;
- invalid tags in `IFT ` mapping entries;
- floating-point `xMin`/`yMin`/`xMax`/`yMax` in `glyf`; a computed bounding box that is
  not an integer fails when it is computed;
- values that overflow after `scaleUpem` fail while scaling, and a units-per-em value
  outside 0–65535 fails before scaling;
- `maxp` values that overflow fail when `maxp` is recalculated;
- featureVars lookup, feature and axis indices above 65535.

fontoxide also parses some data eagerly where fontTools parses it lazily: the whole of
`CFF ` and `CFF2` tables, `CFF2` INDEX items in `VARC` and `COLR` clip boxes. Corrupt data
there fails when the table is read rather than when the broken part is accessed; dumping
to TTX and recompiling access everything, so they fail on both sides. Likewise, a `.ufoz`
archive is read whole when it is opened.

### Recursion limits

fontTools relies on Python's recursion limit (about 1,000 frames) to stop cycles in
fonts. fontoxide has explicit limits, so that it cannot overflow the stack:

- charstring subroutine calls: 500 (valid fonts use at most 10); `seac` nesting: 100;
- component nesting when drawing glyphs from a glyph set (`glyf` and `VARC`): 100;
- `COLR` paint nesting when computing clip boxes: 1,000; unbuilding `COLR` layers: 100;
- SVG subsetting: 990; PostScript procedures (psLib): 900.

They raise a `RecursionError`, as fontTools does. A composite glyph that references
itself is detected directly, with the same message as fontTools but naming the component
that closes the cycle, and composite glyphs have no depth limit.

### Limits on forged sizes

Fuzzing found inputs where a few bytes make fontTools run for minutes and use gigabytes
of memory. fontoxide bounds them:

- a CFF or CFF2 INDEX whose offsets cannot fit in the data is rejected before anything is
  allocated (fontTools: `struct.error`), and an INDEX with an offset size of 0 and items
  is rejected (fontTools reads empty offsets, for minutes with a forged count);
- `Coverage` and `ClassDef` ranges (formats 2 and 4) expand to at most 2^20 (about a
  million) glyphs in total; the rest is ignored with a warning. A real table lists each
  glyph once, and fonts have far fewer glyphs than that.

### Differences by module

**ttLib**

- TTX for `hmtx`/`vmtx` with non-integer `<mtx>` values is rejected; fontTools rounds them
  when compiling.
- `avar` version 2 without `VarIdxMap` or `VarStore` in TTX, and empty `CFF2` INDEX lists
  in `VARC` TTX, compile (as null offsets and empty INDEXes); fontTools raises an error.
- Missing fields in the TTX of the bitmap tables (`EBLC`, `EBDT`, `CBLC`, `CBDT`, `EBSC`)
  and the Graphite tables default to 0; fontTools fails when compiling.
- Glyph names in a `COLR` `ClipList` that are not in the font are dropped when reading
  TTX. The compiled font is the same; a TTX dump of the result lacks those names.
- A `glyf` glyph with a negative `numberOfContours` other than -1, and the reserved byte
  255 in a CFF DICT, are errors when read.
- When TrueType instructions cannot be disassembled, the TTX comment before `<bytecode>`
  contains fontoxide's error message instead of a Python traceback.
- `Font::to_ttx` returns a string and has no output path, so `extfile` bitmap images are
  written to `bitmaps/strikeN/` under the current directory.
- `TSI1`/`TSI3` tables that were never decompiled or imported dump as empty (fontTools
  fails); `TSI1`/`TSI3`/`TSI5` are keyed by glyph ID, so removing glyphs drops their
  entries.
- Non-ASCII `meta` tags, and JSON (`Debg`, `bgcl`) with lone surrogate escapes or nesting
  deeper than 2,000 levels, are errors.
- Graphite: `Silf` subtables with critical features, and `Glat` 3.0 without octaboxes,
  compile (fontTools crashes on both).
- WOFF 2.0: the glyph count is not checked against `maxp` when `glyf` is reconstructed;
  a mismatch fails later, when `hmtx` is reconstructed.
- The `x_mac_*_ttx` codecs apply the `ignore`, `replace`, `backslashreplace` and
  `xmlcharrefreplace` error handlers (fontTools raises a `TypeError`); fontTools itself
  only encodes with `strict`.
- The `FONTTOOLS_GPOS_COMPACT_MODE` environment variable is not read; use
  `Font::gpos_compression_level`.
- For `scaleUpem`, `reorderGlyphs` and `save_xml` inputs on which fontTools crashes, see
  [bugs fontoxide does not reproduce](#bugs-fontoxide-does-not-reproduce).

**Command lines** (`fontoxide ttx`, `fontoxide subset`, …)

- Output always uses `\n` line endings; on Windows, Python writes `\r\n`.
- Text input (TTX from stdin, `subset --unicodes-file` and similar files, VOLT projects)
  is read as UTF-8; Python uses the locale's encoding.
- `ttx --unicodedata` is not supported. `ttx -t`/`-x` with a name longer than four
  characters is an error; fontTools logs that the table is not found and continues.
- Some command lines parse their arguments with a simplified parser, so their usage error
  messages differ: feaLib, voltLib, otlLib.optimize, ttLib.woff2, pens.svgPathPen,
  varLib (build), varLib.mutator, varLib.avar.map, varLib.interpolate_layout,
  ttLib.beyond64k, cffLib.CFFToCFF2 and varLib.instancer. Usage errors of cu2qu, qu2cu,
  mtiLib, varLib.interpolatable and ttLib.woff2 exit with status 1 instead of 2.
- `subset --help` prints only the usage line, and `--timing` has no effect. `-v`/`-q`
  have no effect in varLib.instancer, otlLib.optimize and varLib (build).
- `subset`: code points and glyph IDs that do not fit in 32 bits are errors; fontTools
  treats them as missing.
- `getMacCreatorAndType` (Finder information of Type 1 files on macOS) is not ported.
- The help texts name the program `fontoxide <module>`. With the `fonttools-names`
  feature of `fontoxide-cli`, the `fonttools`, `ttx`, `pyftsubset` and `pyftmerge`
  binaries print fontTools' texts.
- `diff`: an invalid `--color` is reported after other usage errors, with the same
  message and exit status. The time zone offset in the header follows historical
  daylight saving rules; on Windows, fontTools applies the current rules to all dates,
  so the offset of old files can differ in regions whose rules changed.

**subset**

- SVG documents are parsed with a port of lxml's behavior. Documents with a non-UTF-8
  encoding declaration, an external DTD, internal DTD declarations other than simple
  entities, or custom entities in attribute values are rejected as unsupported rather
  than processed differently. Namespace URIs are checked less strictly than libxml2.
  `glyph` IDs accept ASCII digits only.
- A cycle of `PaintColrGlyph` or `PaintColrLayers` no longer makes glyph closure loop
  forever: `PaintColrGlyph` cycles subset normally, and layer cycles end with a
  `RecursionError`.
- A `Device` table that points to a missing delta set is mapped to "no variation" (fontTools
  4.68.0 fails with a `KeyError`; fixed upstream in
  [fonttools#4396](https://github.com/fonttools/fonttools/pull/4396), merged after
  4.68.0). This affects fonts such as Segoe UI Variable.

**varLib**

- instancer: there is no lazy loading; `specializeCommands(generalizeFirst=False)` with
  nested blend lists left over is an error; glyphs imported from TTX without bounding box
  attributes use 0 for the phantom points instead of recomputing them.
- featureVars: `overlayFeatureVariations` does not extend the region lists passed to it
  (the output is the same).
- build and merger: format differences between masters are checked before other
  attributes; merge error messages show glyph IDs where fontTools shows glyph names; a
  `MarkBasePos`/`MarkMarkPos` base record that is missing in all masters is an error
  (fontTools builds a record that cannot be compiled); `MVAR` reads `sxHeight` and
  `sCapHeight` from `OS/2` versions before 2 (fontTools raises an `AttributeError`);
  `hvar.add_hvar` keeps glyphs without variations (fontTools raises an `IndexError`).
- `build_many`: sources of sub-documents are matched to the fonts passed in by file name,
  path, name and layer name.
- `varLib --variable-fonts` supports only literal text and `.`, `\`, `*`, `+`, `?`, not
  full regular expressions.
- interpolatable: where fontTools crashes, fontoxide skips the check or the glyph: open
  contours (contour order check), components and open contours in the start point check,
  component bases missing from sparse masters (with a warning), CFF2 fonts without a
  `VarStore`. Anisotropic designspace locations use the x value. `test_gen` without
  names names the masters by index (fontTools uses the `repr` of a dict).
- `varLib.models -d` with anisotropic locations uses the x value.

**feaLib**

- Integers are 64-bit; overflow is an error.
- `Parser.extensions` (extending the syntax by subclassing) and the deprecated `glyphMap`
  argument are not supported.
- No warning for a `language` statement with several tags.
- A contextual rule that references an empty named lookup is an error when the rule is
  added; fontTools fails when building the lookup.
- `name` statements in `cvParameters` do not rewrite `nameID` in the parse tree.

**otlLib and fontBuilder**

- Glyph classes are `Vec<String>`. fontTools sorts classes given as sets; sort them
  yourself to get the same result.
- `getAlternateGlyphs` does not return subtable breaks (fontTools returns them and then
  fails building `aalt`).
- `buildLigatureAttach` with components without anchors builds records without anchors,
  which compile; fontTools builds `None`, which does not.
- `FontBuilder` rejects unknown field names in `setup_os2` and similar methods; fontTools
  accepts them and ignores them when compiling.

**colorLib**

- `build_colr` always needs the glyph map. Unknown glyph names, missing fields and
  out-of-range integers are errors when building.
- Clip boxes for glyphs that are not in the glyph map are dropped (fontTools keeps them
  in TTX but does not compile them).

**designspaceLib**

- `<lib>` must be a dictionary; empty `labelname`, `familyname` and `stylename` read as
  `""`; unparsable `xvalue` and similar values are dropped with a warning; a `<condition>`
  without a `name` is an error when read.
- Axis `minimum`, `maximum` and `default` default to 0 rather than `None`.
- `filename` and `path` are public fields: setting them directly does not normalize the
  path (`set_filename`/`set_path` do).
- `get_stat_names` and splitting do not update `doc.default`.
- `tostring(encoding="unicode")` is not ported.

**ufoLib**

- Where fontTools fails with `TypeError`, `AttributeError`, `AssertionError` or
  `OverflowError` on malformed data (GLIF elements, plist contents, fontinfo values that
  cannot be converted), fontoxide returns a `GlifLibError` or `UfoLibError`. Without
  validation, malformed groups, kerning, metainfo, fontinfo, lib and layercontents are
  errors rather than returned as is, and so are unknown point types.
- The quick scanners (`getUnicodes`, `getComponentReferences`, `getImageReferences`)
  parse the whole document, so a syntax error late in the file is reported.
- Integers beyond 64 bits become floats.
- A path that escapes the UFO is a `UfoLibError::Filesystem` (fontTools:
  `IllegalBackReference`).
- `.ufoz`: the total uncompressed size is limited to 1 GiB, deflate members with a
  compression ratio above 1032:1 are rejected, and overlapping members are an error (as
  in Python 3.12 and later). Modification times inside the archive are read as UTC
  (fontTools uses local time).
- `GlifPointPen` driven through the `f64` point pen interface writes integral
  coordinates as integers; use `NumberPointPen` for exact control.

**merge**

- Tables that cannot be merged (such as `kern`, `DSIG`, `gvar`) are not parsed first, so
  corrupt ones do not make the merge fail.

**voltLib**

- Text ending with `-`, and numbers beyond 64 bits, are a `VoltLibError` (fontTools:
  `TypeError`, or a big integer).
- `UNICODEVALUES` beyond 64 bits or with non-ASCII digits are rejected.
- Lookup names starting with a letter number or an `Other_Alphabetic` character are
  classified with Rust's `char::is_alphabetic` instead of Python's `str.isalpha`.

**mtiLib**

- Without `--font`, it works (see above).
- Tables store glyph IDs, so two names for the same glyph (such as `glyph00005` and
  `five`) are merged; TTX of the result shows the real glyph name.
- Values that do not fit their binary field, and integers given for device fields, fail
  when parsed.

**psLib, t1Lib, afmLib, svgLib, cu2qu, qu2cu**

- psLib: integers beyond 64 bits become names; `putinterval` mixing arrays and strings,
  `cvn` on byte strings and file objects left from a previous `interpret` are errors;
  reading an unset array element with `get`/`forall` fails immediately.
- Type 1 charstrings: Type 2 operator names in a Type 1 program are dropped with their
  operands when drawing.
- afmLib: the "Generated by afmLib" comment uses UTC (honoring `SOURCE_DATE_EPOCH`); the
  time can be given to `to_text`. Integers beyond 128 bits in attributes are kept as text;
  in character metrics and kerning, beyond 64 bits are errors.
- svgLib: documents must be UTF-8.
- cu2qu (UFO): curve segments with fewer than 4 points are an `Error::Outline`; only the
  first 4 points are used.
- qu2cu command line: glyphs are always drawn from the original outlines.

## fontTools bugs that fontoxide reproduces

To stay byte-for-byte compatible, fontoxide does what fontTools 4.68.0 does, bugs
included, unless the bug is a crash or a hang. These are the ones you might notice. In the
source they are marked `UPSTREAM-BUG(Bn)`, with the number in parentheses below.

**ttLib**

- FeatureVariations 1.0 is compiled with an extra, unused 4-byte `LookupVariationCount`
  (for example in Bahnschrift's `GSUB`); the font stays valid. (B1)
- `VarData` with more word deltas than regions (not conforming to the specification)
  cannot be compiled. (B2)
- `VarComponent`: values of reserved flags are dropped on reading while the flags are
  kept, so round trips of such data are corrupt; flags above bit 31 are cleared when
  compiling. (B3, B4)
- `CFF2` INDEX items: offsets are not checked for order when there are more than 8
  items. (B5)
- An empty `VarIdxMap` cannot be read. (B6)
- `IFT `/`IFTX`: a mapping entry with the entry ID flag but no IDs is written without
  any; the TTX of these tables cannot be read back. (B7, B8, B9)
- Empty AAT lookups cannot be written (`bsln`, `lcar`, `opbd`, `prop`, `ankr`, `morx`).
  (B10)
- An empty `loca` cannot be compiled on its own. (B13)
- A simple glyph without `<instructions>` in TTX cannot be compiled; add an empty
  `<instructions/>`. (B14)
- An unknown operator in a CFF or Type 1 charstring silently ends the charstring. (B15)
- A CID-keyed font whose last glyph has CID 0 can get a charset without its last range.
  (B16)
- With the HarfBuzz repacker, `Coverage` tables of `AlternateSubst` and `LigatureSubst`
  are not forced to the end; the output is valid, just laid out differently. (B17)
- `EBDT`/`CBDT` glyphs of format 8 or 9 with components cannot be dumped to or read from
  TTX. (B21)
- `Ligature.CompCount` read from TTX is one less than from binary, which changes the
  computed `usMaxContext`. (B24)
- After converting to the upper-case beyond-64k tables, loading `hdmx` fails with
  `KeyError: 'maxp'`. (B27)
- An invalid `VDMX` group raises an `AttributeError` instead of an `AssertionError`.
  (B41)
- `scaleUpem` by a factor of 2 or 0.5 makes COLRv1 fonts impossible to save (a
  `PaintScaleUniform` of 2.0). Fixed upstream in
  [fonttools#4405](https://github.com/fonttools/fonttools/pull/4405), merged after 4.68.0.
  (B44)
- `reorderGlyphs` on a CFF2 font renames the charstrings by position instead of moving
  them, so glyphs get the wrong outlines; on CID-keyed fonts, `FDSelect` is not
  reordered. (B46, B47)
- Converting a freshly loaded CFF font to CFF2 (`cffLib.CFFToCFF2`) fails with "CFF2
  CharStrings must form a glyph-order prefix" for many fonts, a regression in 4.68.0. Fixed
  upstream in [fonttools#4404](https://github.com/fonttools/fonttools/pull/4404), merged after
  4.68.0. (B51)
- Converting CFF2 to CFF fails with a `TypeError` for fonts with an `FDSelect`, in the
  instancer's `downgrade_cff2` and in `cffLib.CFF2ToCFF`, a regression in 4.68.0; fixed
  upstream in [fonttools#4401](https://github.com/fonttools/fonttools/pull/4401), merged
  after 4.68.0. Calling `convert_cff2_to_cff` directly works. (B26)
- `ttx -g` does not replace `"` and NUL in glyph file names. (B66)
- Graphite: `Feat` 1.0 settings are read from the wrong offset; `Glat` 2.0 does not
  round-trip; `Silf` before 3.0 with pseudo glyphs cannot be read; opcode 67 cannot be
  disassembled. (B68–B71)
- `ttLib --optimize-font-speed` with only font collections as input fails with an
  `UnboundLocalError`. (B76)

**subset**

- `EBDT`/`CBDT` glyphs of format 8 or 9 keep their old component glyph IDs, and the
  components are not added to the closure. `CBDT` is kept by default, so default options
  can trigger this. Reported upstream in
  [fonttools#4413](https://github.com/fonttools/fonttools/issues/4413). (B22)
- `--recalc-max-context` fails on fonts with `OS/2` version 0 or 1. (B23)

**varLib**

- featureVars on FeatureVariations 1.1: the font is modified (lookups inserted, features
  sorted, `LookupVariationRecord`s left pointing to the old indices) before the error is
  raised. Reported upstream in
  [fonttools#4414](https://github.com/fonttools/fonttools/issues/4414). (B28, B29)
- interpolatable: the "try harder" start point check uses the point count of the wrong
  contour when contours were reordered. (B43)
- CFF2 masters with different hint masks build without the "Hintmask values cannot
  differ" error; the default master's masks are used. Reported upstream in
  [fonttools#4415](https://github.com/fonttools/fonttools/issues/4415). (B49)
- `varLib.avarPlanner` (the old name of `varLib.avar.plan`) exits with status 0 on
  failure. (B75)

**fontBuilder**

- `setup_avar_with_mappings` only accepts mappings keyed by axis index (`"0"`, `"1"`, …);
  axis names fail with a `KeyError`. (B50)

**designspaceLib**

- A `<dimension>` with both `uservalue` and `xvalue` uses `xvalue`; an error is raised
  only when neither is given. (B30)
- On Windows, paths starting with `/` become `//…`. (B31)
- When splitting, the "limiting axis ranges" check keeps mappings it should exclude.
  (B32)

**feaLib**

- Text ending with `0`, `-` or `\` fails in the lexer (fontTools raises a `TypeError`,
  fontoxide a value error). (B33)
- `BaseAxis` ignores its `minmax` constructor argument. (B34)
- An `include` as the last token ends the token stream silently. (B35)
- In a `conditionset`, a condition without values reuses the previous condition's values.
  (B36)

**ufoLib**

- Opening a `GlyphSet` never validates `contents.plist`; errors appear when a glyph is
  read. (B38)
- `writeGlyphToString` with GLIF format 1 writes `identifier` attributes. (B39)

**merge**

- Fonts with a `JSTF` table, or with layout tables that have a `VarStore` or
  `FeatureVariations`, cannot be merged.

**voltLib**

- A glyph defined twice is accepted. (B54)
- Language tags in a script are compared case-sensitively, so `dflt` and `DFLT` can
  coexist. (B55)
- A group referenced twice under another group (a diamond) is reported as "contains
  itself". (B56)
- `voltToFea` with different glyph names in the font maps names twice in alternate and
  expanded ligature substitutions. (B57)

**mtiLib**

- Script tags shorter than four characters get one script record per line. (B58)
- A numeric feature name that differs from its index raises a `TypeError` instead of an
  `AssertionError`. (B60)

**cu2qu, psLib, t1Lib, tfmLib, svgLib**

- `fonttools cu2qu` reports every glyph as modified and rewrites it, turning integer
  coordinates into floats. (B61)
- psLib's `store` also defines the name in the current dictionary. (B62)
- Compiling a Type 1 charstring with float operands raises a `TypeError` instead of the
  intended message. (B63)
- tfmLib: more than 256 extensible characters raise a `NameError`. (B65)
- svgLib: an arc with radius 0 draws nothing (the SVG specification draws a line). (B67)

**diff**

- `--color auto` (the default) always writes colors, even when the output is not a
  terminal. (B72)
- With `-t`, if all the given tables are identical in binary, all tables are dumped and
  compared. (B73)
- Errors while comparing binaries (such as a collection without `--y1`) are not caught:
  exit status 1 instead of a `[*] ERROR` line and status 2. (B74)

A few other reproduced bugs only affect the wording of error messages.

### Bugs fontoxide does not reproduce

Where fontTools crashes or hangs, fontoxide does the sensible thing instead:

- `scaleUpem` skips `kern` subtables of unknown formats and glyph components positioned
  by points (fontTools: `AttributeError`). (B45)
- `reorderGlyphs` skips null coverages, as in `MATH` tables built without extended
  shapes or horizontal variants (fontTools: `AttributeError`). (B48)
- `save_xml` without the version and with split output still writes the version
  (fontTools: `UnboundLocalError`). (B52)
- mtiLib: a mixed-case `Subtable End` is an error (fontTools loops forever). (B59)
- Forged CFF INDEX offset sizes and `Coverage`/`ClassDef` ranges are bounded (see
  "Limits on forged sizes"; fontTools takes minutes). (B77, B78)
- Graphite `Silf` with critical features and `Glat` 3.0 without octaboxes compile (see
  above).
